# Coding standards for reviewers

Judgement calls that no tool can check. Fmt, clippy, control bytes and duplicate note headings are checked by machines (`.githooks/pre-commit`, CI); Note JT9 lists the rest (scan tests, clippy lints, the doc lint, further hook steps). Report a violation of a rule here as a finding, citing the rule.

- **A RED comes from real behaviour.** A failing test proves a fix only if it failed on the old behaviour, or a mutation of the new code makes it fail. A compile error against a function that doesn't exist yet proves nothing about behaviour.
- **Numbering schemes convert at the boundary.** An integer that has several numbering schemes (raw TXST index, 0-based NIF slot, 1-based `slotN`) states which one it holds at its declaration, and is converted once where it enters the code. Check every new read of such a value against its source: `txst_slot.slot` is a raw TX index, and TX02 is not slot 3.
- **Tests go through what gets written.** A test of a name, path or mapping checks the output that reaches disk or the record that reaches the game, not only the input name it started from.
- **A cache key covers everything the builder reads.** For each new input to a cached computation, find the key and confirm the input is in it. A new field read by the builder and missing from the key is a stale-cache bug.
- **The fast re-plan keeps what the full plan keeps.** For the state the fast re-plan (`apply_partial`) owns (the scope sets' items, sets, producers and views), what the full plan keeps the fast re-plan keeps too, and what the full plan drops it drops. The rest (export blocks, asks, mesh votes, checks) stays as of the last full plan on purpose, until the full plan lands behind the partial. An edit to the project document (the TOML) calls `touch()`. An action that waits a frame (a deferred click, a dialog answer) is checked against the state after the plan lands. A test pins each path on its own.
- **A menu command does something in every state that shows it.** Hide or disable a command the current state can't act on. A click that silently changes nothing is a bug.
- **A long `#[ignore]` run keeps its per-item results.** A test or bench that is `#[ignore]` and takes longer than about 10 minutes writes its per-item results to a file: per input file or block range, a hash of each output it compares, or each score. The file lives outside the repo or in a gitignored folder, never committed, and its path comes from an environment variable or an argument. Its first line names the commit and the input set. A later run checks against that file instead of recomputing everything. The 10k-texture corpus run of `bcenc` is the case that prompted this.
