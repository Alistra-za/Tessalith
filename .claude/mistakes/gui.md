# Mistakes: GUI (crates/gui)

Format and rules: [README.md](README.md).

- 2026-11-01 An egui kittest hung on `run()` → a viewport that never goes idle (a spinner, the 3D view) needs `run_steps(n)`, not `run()` (`crates/gui/tests`)
- 2026-11-01 A `SetsDoc` / `ProjectDoc` mutation served stale data → mutate first, then call `touch()`; `entries()` is cached by revision, so a mutation without `touch()` serves stale data (Note BI) (`crates/gui/src/sets_doc.rs`)
- 2026-11-01 "The button does nothing" on a big project was the panel showing the last plan while an ~18 s re-plan ran, and a kittest on `ui::draw` alone never ends a plan (only `SdcApp`'s frame polls the model) → reproduce with `eframe::App::ui` on `SdcApp` or call `wait_idle`, and keep panel edits behind `fix_off()` (Note FK) (`crates/gui/src/ui/settings_panel.rs`)
- 2026-11-01 "Planning…" as a `review_gate` reason disabled Review's Export during the plan a focused field's commit starts, breaking Note FC8's one-click commit and export → show plan state beside a live button and let the click queue (`crates/gui/src/model/review.rs` `review_gate`, test `input_name_edit::review_export_click_commits_the_field_and_runs`)
- 2026-11-02 A model-driven timing harness drew no frame after each settle, so the next partial found the views cache cold and paid a full rebuild → call `views()` and `problems()` after every `wait_idle`, as the app's frame would (`crates/gui/tests/replan_timing.rs`)
- 2026-11-04 An edge test checked labels against the viewport `width`, but `allocate_ui(vec2(width, ..))` starts inside the harness' 8 px margin, so the drawer really ends at `width + 8`; wrapped text near the edge passed or failed by the temp-dir path length (CI's `runneradmin` is longer) → record `ui.max_rect().right()` inside the allocated ui and assert against that (`crates/gui/tests/advanced.rs`)
- 2026-11-07 A mutation of the writer index's self-exclusion survived because the fixture's host id sorted after the consumer, so first-writer-wins never reached it → for a first-writer rule, name the fixture so the set under test sorts first (`crates/gui/tests/txst_map.rs`, `txst_map::written_index`)
- 2026-11-09 A hover's `h.run()` right after a replay panicked "exceeded max_steps (4)" under full-workspace load: `settle`/`wait_idle` skip the background workers (dims, used_by, DDS thumbs) whose poll at `app.rs` `worker_poll` keeps asking for repaints → call `app_harness::quiet(&mut h)` after the replay, before looking up the rect to hover (`crates/gui/tests/ui_proof/sets_column_pins.rs`)
- 2026-11-09 A right-aligned ✕ in the set editor sat under the floating scroll bar of the `centre-set` area, and kittest's `Node::click()` presses at the node's rect centre, so the bar took the click and the button never fired → leave `bar_width + bar_outer_margin + item_spacing.x` free on the right of a row there, and call `scroll_to_me()` then `run()` before a pointer click (`crates/gui/src/ui/set_editor.rs::shared_rows`)
