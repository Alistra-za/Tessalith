# Mistakes: GUI (crates/gui)

Format and rules: [README.md](README.md).

- 2026-11-01 An egui kittest hung on `run()` → a viewport that never goes idle (a spinner, the 3D view) needs `run_steps(n)`, not `run()` (`crates/gui/tests`)
- 2026-11-01 A `SetsDoc` / `ProjectDoc` mutation served stale data → mutate first, then call `touch()`; `entries()` is cached by revision, so a mutation without `touch()` serves stale data (Note BI) (`crates/gui/src/sets_doc.rs`)
- 2026-11-01 "The button does nothing" on a big project was the panel showing the last plan while an ~18 s re-plan ran, and a kittest on `ui::draw` alone never ends a plan (only `SdcApp`'s frame polls the model) → reproduce with `eframe::App::ui` on `SdcApp` or call `wait_idle`, and keep panel edits behind `fix_off()` (Note FK) (`crates/gui/src/ui/settings_panel.rs`)
- 2026-11-01 "Planning…" as a `review_gate` reason disabled Review's Export during the plan a focused field's commit starts, breaking Note FC8's one-click commit and export → show plan state beside a live button and let the click queue (`crates/gui/src/model/review.rs` `review_gate`, test `input_name_edit::review_export_click_commits_the_field_and_runs`)
- 2026-11-02 A model-driven timing harness drew no frame after each settle, so the next partial found the views cache cold and paid a full rebuild → call `views()` and `problems()` after every `wait_idle`, as the app's frame would (`crates/gui/tests/replan_timing.rs`)
- 2026-11-04 An edge test checked labels against the viewport `width`, but `allocate_ui(vec2(width, ..))` starts inside the harness' 8 px margin, so the drawer really ends at `width + 8`; wrapped text near the edge passed or failed by the temp-dir path length (CI's `runneradmin` is longer) → record `ui.max_rect().right()` inside the allocated ui and assert against that (`crates/gui/tests/advanced.rs`)
- 2026-11-07 A mutation of the writer index's self-exclusion survived because the fixture's host id sorted after the consumer, so first-writer-wins never reached it → for a first-writer rule, name the fixture so the set under test sorts first (`crates/gui/tests/txst_map.rs`, `txst_map::written_index`)
- 2026-11-09 A hover's `h.run()` right after a replay panicked "exceeded max_steps (4)" under full-workspace load: `settle`/`wait_idle` skip the background workers (dims, used_by, DDS thumbs) whose poll at `app.rs` `worker_poll` keeps asking for repaints → call `app_harness::quiet(&mut h)` after the replay, before looking up the rect to hover (`crates/gui/tests/ui_proof/sets_column_pins.rs`)
- 2026-11-09 A right-aligned ✕ in the set editor sat under the floating scroll bar of the `centre-set` area, and kittest's `Node::click()` presses at the node's rect centre, so the bar took the click and the button never fired → leave `bar_width + bar_outer_margin + item_spacing.x` free on the right of a row there, and call `scroll_to_me()` then `run()` before a pointer click (`crates/gui/src/ui/set_editor.rs::shared_rows`)
- 2026-11-10 The type cleanup (Z11) missed the fast re-plan: `type_base` was kept only in `apply_plan`, so a partial that landed first had already replaced the items with the new sub-types → state kept before a plan must also be kept before a partial (`crates/gui/src/model/mod.rs` `apply_partial`)
- 2026-11-10 Rename checked a new set name only against the cards (`taken_ids`), so it took the id of an automatic set that was deleted or emptied by a move; the engine still makes that set, refused the Rename, and the entry was left naming no files → check a new set id against every file's automatic id (`auto_id`), not just the visible cards (`crates/gui/src/model/sets.rs` `rename_set`)
- 2026-11-15 A view value built from a new item field (the diffuse's alias) went stale on the fast re-plan only in a created set: a renamed or automatic set's id moves with the alias, so tests on those passed with the field missing from `view_reads` → add every item field `finish_view` reads to `sets::view_reads`, and pin it with a created set (`drop_new_set`), whose id never moves (`crates/gui/src/model/sets.rs` `view_reads`)
- 2026-11-16 Scoping `ScrollStyle::thin()` on a column took 6 px from its content and dropped the Sets cards from five chips a row to four at the default width, and moved a test that told a dialog row from a card by rect → after a scroll-style change, check wrap points at the default widths and any test that tells widgets apart by rect (`crates/gui/src/ui/sets_column.rs`, Note JJ2)
- 2026-11-16 `sed -i` rewrote CRLF to LF in the egui 0.37 spike → do mechanical rewrites with a `py -3.13 -I` script that reads and writes bytes, keeps CRLF and asserts each match count before it writes (`crates/gui`, Note J?)
- 2026-11-16 `cargo fmt` rewrote every file it reformatted with LF line endings, and the Write tool creates new files LF → after fmt, run `git ls-files --eol crates` and restore CRLF on any `.rs` at `w/lf`: `git add` the file, delete it and `git checkout -- <file>`, or convert it with a byte script that asserts every LF becomes CRLF (`cargo fmt`, Note J?)
- 2026-11-16 A bare `Context::run_ui` probe panicked "Dropped TexturesDelta with 1 unapplied deltas" on epaint 0.37 → call `textures_delta.clear()` on each `FullOutput`, or build the probe with `egui_kittest::Harness` (`crates/gui/src/ui/panel_ids.rs` tests, `crates/gui/src/look.rs` tests)
- 2026-11-16 A restored panel width read back as the panel's 200 px minimum: an egui side panel stores its frame's response, so an empty panel shrinks to its content and cannot hold a restored width → give a width test content that fills the panel, or read the stored width (`panel_ids::pending_size`) (`window_layout::a_saved_meshes_tree_width_comes_back`, Note J?3)
- 2026-11-16 the kittest suite passed with a combo 62 px out of place → after any look pin, render the doc shots (`tools\doc-shots.ps1`) and open every overlay; they are the look's acceptance test (Note J?2, J?8)
- 2026-11-16 On egui 0.37 a `run()` right after an edit that starts the worker raced the plan's result and passed or failed "exceeded max_steps (4)" by timing: each new widget asks for one more frame (`Ui::widget_style`) → after the edit's click or key, `step()`, then `wait_idle`, then `run()` (`crates/gui/tests/resize_field.rs` `pick_in`, Note J?8)
