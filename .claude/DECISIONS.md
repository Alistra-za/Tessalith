# Decisions record

Live rulings for Tessalith 2.x. Three files hold the record:
- this file: the index, a digest of the 1.x rulings still in force, then the 2.x notes (Note FM first) in full;
- `.claude/DECISIONS-1.x.md`: the 1.x record, frozen at 2.0 (history only; its IDs stay citable);
- `.claude/DECISIONS-ARCHIVE.md`: superseded 2.x rulings.

A new note goes at the end of this file and adds its letter to the index line of every crate or area it governs. A letter is free only when none of the three files uses it.

## Digest

Rules still in force at 2.0, one or two lines each, with the 1.x IDs (in `.claude/DECISIONS-1.x.md`) or FM items they come from. Where a 1.x ruling and Note FM disagree, FM wins. The 1.x note holds the reasons and details; a cite is where to read them. `OPEN:` lines are promised work not done yet.

### Engine policy

- For texture artists converting source images to DDS for Skyrim SE/AE, not a game-folder DDS fixer; suffix inference proposes, the user decides category, encoder and settings. [Scope clarification]
- Windows only. [Answers 12]
- The product is Tessalith (GUI `tessalith.exe`); the CLI stays `sdc`. [F, AG1]
- BC4 and BC5 are unsigned; SE loads both legacy `BC4U`/`BC5U` FourCC and DX10 `BC4_UNORM`/`BC5_UNORM`. [Answers 2]
- BC6H (emissive, sky) works under Community Shaders only, never vanilla; `_SRGB` formats are not usable with vanilla shaders. [Answers 3, Answers 4]
- Any colour data in a PBR set is `_SRGB`-tagged (including `_g`, `_f`). [Answers 5]
- Two-channel BC5 is the default only for `_flow`; it stays selectable. [Answers 1]
- No small-texture restriction on BC7. [Answers 7]
- Normal length: renormalise, unless the set has an `_rmaos`/`_rfaos`, in which case the normal variance is baked into roughness. [Answers 6, R1, R6]
- Alpha that must read 255 is removed before any mip or encode step (alpha policy `remove`). Every BC7 block whose input alpha is 255 throughout gets the lossless rotated-slot fix, so bc7e decodes alpha ≥ 254. [Answers 8, A]
- CS treats smallest-mip alpha < 251/255 as complex material, so a decoded 254 is harmless. [A, BJ1]
- Source alpha with minimum ≥ 251, or with texels below 251 that are only stray noise, is opaque; it resolves like constant 255. An explicit `alpha.policy` still wins. One alpha gate, 251, matching CS. [L, BJ1, FM34]
- Cutout vs blend is a per-image choice; the alpha-test threshold is per texture (default 127, typical 5–200). Coverage preservation is on by default for Cutout and Cutout+Blend. [Answers 10, E]
- `_rfaos` = Roughness, Fuzz, AO, Specular: `_rmaos` with a fuzz mask in G; linear data, alpha = specular, same bake. [B]
- Intentional skips (existing `.dds` inputs, `--on-existing skip`, packing inputs) do not make the batch exit 1; unresolved, blocked, unknown existing outputs and failures do. Skips are still reported and counted. [I, M4]
- Hair diffuse is cutout + blend by default; a `multilayer` diffuse's alpha is data. [AK1, S-shader-5]
- Plain normals (`_n`, `_normal`, `_norm`) default to DirectX green; `IN-GREEN-UNSTATED` is Info; explicit settings win unchanged. [AW1, AW2, AW3, W13]
- A packed map cannot use an HDR format (BC6H and packing are mutually exclusive). [S12]
- `pbr_emissive` is BC6H only when the source is float and some finite RGB value exceeds 1.0; otherwise BC7 sRGB. `hdr_sky` is BC6H whatever the source. [O2, S3]
- A float source (float TIFF, EXR, HDR, float DDS) is linear light; Preprocess never sRGB-decodes it. [S1]
- OpenEXR alpha is un-premultiplied on load. [BQ15]
- `IN-NONFINITE` is reported once at plan time; statistics skip non-finite samples. [S9, BC6]
- An embedded ICC profile is ignored and not reported. [S8, FM21]
- Game-path keys (meshes, scan, BSA) fold ASCII only; set ids and `[files]` keys fold Unicode. [BF1]
- Files the user edits and DDS outputs are written with `engine::dds::write_atomic`, which flushes before the rename. [BC10, AV item 13]
- One rule for replacing an existing file; never overwrite a file Tessalith did not write. [BV3, BC2]
- The engine is MPL-2.0 (with `encoders-sys`); no commit may call it MIT. [DC41]
- The workspace version is the engine version; it follows semantic versioning (MAJOR breaks use, MINOR adds features, PATCH fixes). [DM8, DB1]
- Engine 2.0.0 has one encode version for every type; a 1.x record is a stale baseline and re-encodes once. [FM9, DM1]
- Removed config keys and values are errors that name the fix; the old-version upgrade code is gone, newer-version refusals stay. [FM10, FM13, T9]
- Fifteen info and low-value warning codes and the re-encode report are gone; anything the user must act on is a code with a fix. [FM21]
- An engine change that alters a type's bytes or verdict moves that type's arm in `encode_version` (Note DM); the byte-identity pins in `encode_versions/identity.json` are strict. [DM1, DM4, FM1]
- A new `Profile` field is `#[serde(default, skip_serializing_if = …)]` so existing profile hashes hold. [DM5, S-mips-9]
- `RELEASED_ENGINE_VERSION` is set by the release commit to the released version. [DM5b, FF8, FM41]
- Engine modules `coverage`, `dilate`, `migrate`, `pipeline` and `sysmem` are `pub(crate)`. [FA14]
- One set-base rule: `engine::group::base_of`. [FA13]
- `toml` 1 is the parser. [BL]
- Test-only hooks sit behind each crate's `test-hooks` feature (off by default, on through the crate's own dev-dependency, never in release); `sdc-gui`'s also forwards render3d, modscan and pgpsim `test-hooks`; render3d's hooks are `#[doc(hidden)]`. [K, FM27, GJ2]
- Dev and test builds keep line tables only. [FM2]
- The bench crate and raw tuning data live on local branch `bench`, not `main`. [FM8]
- NVTT is gone from the code; it is never bundled. [FM14]
- Cs and vanilla are the only targets; there is no `cpm` target. Complex material is a vanilla shader and complex grass is available under vanilla. [AZ5, AZ6]
- Planning order: pass 1 resolves every file, then each set's shader is picked; members of shaders with defaults or sub-type effects re-resolve; a panic is isolated per file; explicit shader picks are read before the packed-suffix prediction. `SHADER-*` warnings ride on `set_resolved`. `EVENT_SCHEMA` stays 2 while a change only adds fields or drops an enum value. [S-shader-7, AZ4, AW4]
- `Engine::plan_full` is `prepare` (setup, discovery, `[files]`, grouping, joins, typed roles, set edits, duplicates) then `plan_sets` (pass 1 onward); every edit still runs a full plan, which lands last and wins, and Export and Review run only on it. [FL2, FL9]
- `Need` is `subtype` or `alpha_meaning`; the green convention never makes a job Unresolved, so `unresolved_code` returns only `SUG-LOW-CONFIDENCE`. [AW4]
- Discovery keys each file by its canonical path: the first input to reach a file wins and a link and its target are one file. An unreadable entry under an input folder is `IN-UNREADABLE` (warning) and the batch goes on; an unreadable input root is an error. [BQ1, Y4]
- A game path cuts at the first `textures` component at or below the input root's last component, else the last one anywhere, else the relative path. A `textures` folder below the root wins over the root's own; a root named `textures` that holds mod folders keys from the mod's own `textures`. [BQ8]
- Glob errors by entry point: `--set file:<glob>` is a usage error, preset rule globs a preset error, config and alias-preset globs a config error; the compiled-matcher cache is lazy, never evicted. [BC5, Y4]
- A PNG decodes with a 64 MiB metadata budget (`load::PNG_METADATA_BUDGET`); other formats have none. Decoded pixels are not counted, so a 16384 px RGBA16 PNG still loads. [AV1]
- PSD/PSB are inputs (not Krita or OpenRaster): RGB or Grayscale, 8/16/32 bits; alpha is the document transparency (first alpha channel with a Background layer); a white-matted composite (negative layer count or `Mtrn`/`Mt16`/`Mt32`) is un-matted with `(c − (1 − a)) / a`. Bitmap, Indexed, CMYK, Multichannel, Duotone, Lab, no real composite or a ZIP composite is `IN-DECODE` with the reason; over 16384 px is `DIM-TOO-LARGE`. [AC2, AC3, AC4, FM23]
- `.exr`, `.hdr`, `.bmp` and `.jpg`/`.jpeg` load through the `image` crate; an undecodable file is `IN-DECODE`. [S10]
- Memory admission: a plan-pass cache hit admits at 0 bytes, a cold file costs one stat; a job over the budget runs alone when nothing else is in flight; RNM layers add at the resized base size and a bake's layers at the `_n`'s resized size (sums); a photo cube adds `2 × w × w × 16`; a helper's decode bytes count beside its target's. [AV4, BB2, BB3, BB5, DS19, DY10e]
- A `_crn` makes a set PBR like `_cnr`. [BV9]

### Analysis and alpha

- The alpha question is one dropdown on the resolved type. [FM35]
- No-suffix files are the colour member, at High confidence; the GUI accepts High suggestions and records them in the project. [U1, U3, FC1]
- Mesh alpha evidence (NiAlphaProperty from the scan) decides a varying alpha's meaning through the `mesh:alpha` layer; the first plan asks until the scan evidence is read, then re-plans. [U5, U6, U7, U9]
- "(auto)" in the Sub-type row means the decision came from evidence, with the reason on hover. [U4]
- `_coat` is coat colour + strength (canonical `s`). [U2, S-shader-9]
- A complex `_m` without source alpha writes alpha 0; "Enable parallax" on its card keeps the height (off sets alpha 0). [AH1, AH2, M1]
- Alpha noise near 255 counts as opaque. [FM34]
- The BC3 alpha guard follows each texture's alpha-test cutoff. [FM19]
- Coverage (`VAL-COVERAGE`) runs on every mip level, also under `validation.mips = smallest`; PSNR then checks the last mip only. [T5, Y6]
- Artist checks run from analysis stats cached with the analysis; hints come from the canonical suffix; in the GUI they are one count, not amber, not ready signals, never Review (rows plus one end-of-export summary). [CL1, CL2, CL6, FC3, CL18, CL25]
- The analysis disk cache: `ANALYSIS_VERSION` alone versions it, the hints are part of every key, same size and mtime is "unchanged", a value that does not read back bit for bit is not stored, every I/O error is a miss, prune keeps the newest 200 MB. [DZ1, DZ3, DZ5, DZ6, DZ8, DZ9]
- Only `main.rs` reads `LOCALAPPDATA` for the analysis store; the GUI builds one `Session`. [DZ10, DZ11]
- A float (EXR) colour map is kept as stored values. [CN24]
- An Advanced-skin diffuse switches its set's packed RMAOS to RFAOS, both ways; a pinned diffuse is left alone. [DQ1, DQ3, DU, DW]
- The engine reads the chosen shader as Advanced-skin evidence; GUI and CLI agree; written values win. [DV, DW]
- A written plain `diffuse` on an Advanced Skin set reads as `skin_albedo`; any other written sub-type stays; a written `packing.recipe` decides the packed output alone. While the shader is Advanced Skin the diffuse cannot be plain `diffuse` (leave Advanced Skin for that). Vanilla is untouched. [DV3, DV1]
- A diffuse in a pinned slot turns the shader reading off for its set. The GUI sends locked slots' `[files]` keys as `BatchRequest::pinned_files` (a borrowing set's lock left out); the CLI sends none and never reads `sdc-project.toml`. `pack::plan::chosen_skin` is the one predicate. [DW1, DW2, DW3]
- A set that cannot build `_rfaos` (metallic-only sources, `PACK-RECIPE-UNBUILDABLE`) still takes the Advanced-skin sub-type and keeps `_rmaos`. [DQ2]
- Check stats ride in the cached `Analysis`: `AnalysisCache::checks` is off by default and on in `Session::new`; the CLI computes none, so CLI output, manifests and goldens do not change. [CL3]
- Green direction check: a Normal-category job other than `msn` whose blue mean is below 0.5 (not for BC5/RG8, which store no blue) raises `CHK-Z-SIGN`; as-stored curl above `CURL_FLOOR` (1e-4) with flipped curl under `GREEN_RATIO` (0.5) of it raises `CHK-GREEN-GUESS`, unless the profile already flips green. `CHK-GREEN-GUESS` is Info and never auto-flips. [CL7, CL10, CL8]
- Parallax check reads the `_p` in R (a complex `_m`'s A when parallax is on and the source has alpha) against the set's neutral: White for a Pbr set with multilayer and coat parallax on, none for vanilla Multilayer, else Half; it flags clipping over `CLIP_SHARE` 0.10 and steep steps over `STEEP_SHARE` 0.03. Landscape sets compare `displacement_scale`: a ratio over 2 (two sets) or more than 2× from the lower median (three or more) raises set-level `CHK-PARALLAX-SCALE`. [CL11, CL12, CL8, FM26]
- `CHK-UV-GUTTER` flags a texture whose gutter share is over `GUTTER_SHARE` = 0.02. [CL34]
- `CHK-LOW-DETAIL` (Warning) is the one CHK code the engine emits, measured during convert after coverage preservation, behind `BatchRequest::low_detail` (`Off` by default; never set by the CLI). Ratio: detail energy between mip 0 and nearest-up mip 1 over that between mips 1 and 2; below `LOW_DETAIL_RATIO` 0.25 flags. Eligible: `resize = none`, Color or Normal, not `complex_grass`, ≥ 3 levels, a power-of-two size `resize = half` would shrink above the floor; never a cube; bytes and records unchanged. [CL20, CL22, FM26, DS5]
- Under cs, hair has an optional suffix-only `_flow` role and an auto rule `flow` picks `hair` for a set with a `_flow` member on both targets, unless the path has a `water` folder; under vanilla a `_flow` still raises `SHADER-EXTRA-MAP`. [CL35, CL36]
- A complex-grass job has no base coverage and raises no `VAL-COVERAGE`: the top half is preserved in `grass::build` and the bottom half's alpha is specular data. [BC3, BC13]
- Complex grass has no alpha question (varying alpha: top half cutout, bottom half data); its set gets no `SHADER-EXTRA-MAP` / `SHADER-MISSING-MAP`; a grass stem ending in a raw-map or layer suffix is read as that. [X12, X9, X8]
- A constant alpha-0 block of a `complex_material` with `alpha.parallax` off gets `encoders_sys::bc7_fixup::force_zero_alpha` after the encode (bc7e would otherwise decode alpha 1); BC3's alpha block stores 0 exactly. [BC7]
- The analysis cache admits with the load's hints, so an admission hit is a load hit; a disk entry without a thumbnail misses when thumbnails are wanted; the CLI caches nothing. `tests/analysis_version.rs` hashes generated PNGs, engine DDS files and `pack::assemble` results, so a loader change moves `ANALYSIS_VERSION`. [DZ2, DZ7, DZ4]

### Mips and resize

- The default mip filter is `box` for every sub-type and preset. [S-mips-1]
- Non-box filters need sRGB colour; tent, mitchell and kaiser levels are built directly from mip 0 with the kernel widened per level. [S-mips-2, S-mips-3]
- On alpha-weighted colour (`cutout`, `blend`, `cutout_blend`) the filter is box or tent; Mitchell and Kaiser are barred (they ring at cutout edges); HDR with alpha weighting takes box only. Weighted tent keeps the box alpha bit for bit. [FM28]
- Kaiser is fixed at width 3, α 4, stretch 1; Mitchell is B = C = 1/3, radius 2; tent radius 1. [S-mips-4]
- `mips.edge` = `wrap` (default) or `clamp`; only the polyphase kernels read it. [S-mips-5]
- An unscoped filter only affects colour maps, with a console message. [S-mips-13]
- Normal, `_msn`, `_flow` and roughness chains are never alpha-weighted. [R11]
- Normal mip 0 is renormalised by default (`mips.normal_base` = `renormalize` or `keep`). [R1]
- Power of two is automatic; `resize` is Half, Quarter or Eighth with a size floor, optionally relative to a slot of the set. [FM29, FM44]
- Pack sources of different sizes are resized to a common size. [FM30]
- `DIM-SMALL` and `DIM-FLOW-SMALL` test the post-resize size. [S-mips-7]
- Complex grass: each half is mipped on its own and the levels stacked; the detection texel is re-encoded to stay exact. [X1, X2]
- Coverage reference after a resize is the resized mip 0. [S-mips-8]
- Resize runs at the end of `preprocess_with` (after the Hdr clamp; the pipeline and `BakeJob::load_lengths` both call it) with the effective mip filter and edge: box is area-exact, tent, Mitchell and Kaiser are polyphase on RGB; alpha is area box; alpha-weighted colour weighs area × alpha; roughness resizes on r²; normals, `_msn` and `_flow` resize as vectors, mip 0 renormalised unless `mips.normal_base = keep`. A growing axis is first enlarged bilinearly (texel centres, clamped edges); axes scale independently. [S-mips-6, W10, FM29]
- Coverage preservation passes exactly `k = round(p·n)` texels on every level ≥ 1: those above the k-th largest alpha plus enough ties, split in a deterministic hierarchical Bayer order (no RNG; owner asked for the dither). `k = 0`, or a level with no positive alpha, keeps the box alpha; zero alpha is never raised. Remapped texels sit at least 2 codes clear of the threshold, saturating at the range ends (`alpha.threshold` 1–254). [R13]
- A hair diffuse's default layer sets `alpha.policy = cutout`, so a user's `mips.filter = kaiser` or `mitchell` on it is `CFG-INVALID` at sub-type or file scope and falls back to box with `CFG-FILTER-IGNORED` when unscoped. [S-mips-0, S-mips-2, S-mips-13]
- OPEN: match a resized mip 0's coverage to the source's. [S-mips-8]
- OPEN: the 13 GiB box peak at 16K and the single-threaded per-channel `powf` in Preprocess. [S-mips-11]
- OPEN: the complex-material gloss mip is the mean of gloss, not of α ("average α if banding shows"). [CL40]

### Encoders

- The format alone picks the encoder; the rgbcx level is fixed; the mode-6 byte patch is gone. [FM15]
- BC1 and the colour half of BC3 encode with rgbcx Dual (NVIDIA + AMD decoders); there is no decoder setting. [FM17, FM18]
- BC1 is opaque unless `encoder.bc1_alpha` is on (opt-in 1-bit alpha). [F, FM20]
- Perceptual BC1; vanilla colour is perceptual. [FM42, FM43]
- BC1 and RGB8 are allowed on a `data`-alpha type when the alpha is empty. [FM39]
- BC7 weighting is a dropdown with a stated precedence; inherited values are overridable; RMAOS weighting R4 G1 B2 A1 was dropped. [CP1, CP3, CP9, CP12]
- bc7e has an effort level `max`, off by default; the default stays byte-identical; level hashes are pinned per ISPC target; the endpoint search is not adopted in `veryslow`. [BZ1, BZ2, CB2, CB4]
- BC6H defaults to the peak-preserving mode (ISPC TC patch 0001); Slowest and Max use it. [FE3, FF1, FM43]
- BC4 block search: inner-anchored 6-value mode, least-squares refits, trimmed and local search, never worse per block; it carries a manifest tag. [FJ1, FJ2, FJ4]
- BC4/BC5 search radius as measured. [T11]
- The rgbcx rounding patch is applied. [T13]
- `encoder.bc7_weights` (the BC7 weighting dropdown) is optional and serialised only when set (existing profiles, presets, hashes and `sdc.toml` stay byte-identical). The weights reach bc7e only (other formats raise `ENC-WEIGHTS-IGNORED`); `encode_band` calls the tuned entry only with weights set and perceptual off, else the exact plain call; unit weights give the plain bytes. No preset, sub-type or rule sets it. [CP2, CP4, CP5, CP8]
- The GUI writes Linear as cleared fields; when an inherited perceptual or weighting is in effect it writes `perceptual = false` and `bc7_weights = "linear"` in the texture's own entry. [CP7, CP10]
- bc7e output depends on the CPU's ISPC target, so an AVX2 machine and an older one can write different BC7 bytes; the goldens hold on AVX2 machines. [CB3]
- Partition breadth without refinement is not a lever (bc7e refines only the winner; `m_refine_partitions` is part of `max`); `slowest` stays upstream's; per-channel normal weights are not adopted (they worsen Z, which Skyrim reads). Enabling the endpoint search (+0.05 dB colour at 1.4× time) would change every BC7 output, so it is an owner ruling. [BZ4, BZ3]
- The BC6H peak mode is a field value: on when a `bc6h_enc_settings` has both `slow_mode` and `fast_mode` (no upstream profile does), so no struct or ISPC header changes; the shim's `g_bc6[5]` is veryslow plus `fast_mode` (`Bc6hLevel::VeryslowPeak = 5`). `encoders-sys` `tests/bc6h.rs` pins the AVX2 output of the five levels; the owner accepted its +0.6 % RMSLE miss. [FE2, FE4, FE7]
- The complex-grass corner retry re-encodes at `Effort::Slowest` through `encode_band` (the LDR path, BC7 only), so it never reaches BC6H. [FF2]
- The BC3 coverage guard covers alpha only (BC4/BC5 are data). The new BC4/BC5 search also runs at radius 4 for the fast presets (`cs-compact`, `vanilla-compact`, `fast-preview`); it costs about 2.5× the old BC4/BC5 time at radius 4. The near-exhaustive `max` search was declined by the owner. [FJ7, FJ3, FJ8]
- Uncompressed outputs: `rgba8` (B8G8R8A8 UNORM/SRGB), `r8`, `rg8`, `rgba16f` (`cs` only). [O1, S4]
- Legacy uncompressed DDS: 24-bit RGB is read and written, A8L8 and L16 are read. [FM38]
- A `gray` sub-type: BC4 or R8, red by default, picked by hand; `channels.grayscale_source` picks R, G, B, A or luma. [FM36, FM37]
- OPEN: the non-AVX2 ISPC paths (SSE2/SSE4/AVX) of the BC6H peak mode were never hash-checked; `tests/bc6h.rs` skips without AVX2. [FF7]

### Packing and helpers

- Suffix vocabulary follows industry names; `_normalgl`/`_normaldx` resolve automatically. [H]
- Missing packed channels get neutral defaults plus a warning (AO white, metallic black, specular alpha white); roughness default 0.5. Fills are per packed output, `packing.fill.<role>`, 0–255. [H, M5, R-fills-2]
- `packing.recipe` = `auto`, `rmaos` or `rfaos`; `rfaos` without fuzz uses the fuzz fill. [R-fills-1]
- Advanced skin sub-types: `skin_albedo`, `skin_rf`, `skin_sk`, `skin_wet`, `skin_detail` (HB4). `rfaos` is not a sub-type id. [R-skin-1, R-review, FM11]
- A skin `_f` fills the RFAOS fuzz mask in a set already Advanced skin by other evidence; `_f` never makes a set Advanced skin by itself; a real `_fuzz`/`_sheen` wins G. [DR1, DR2, DR3, DR7]
- Env mask: a complex-material `_m` R is the metallic source, else specular, else the fill. [M1]
- Raw maps without a recipe raise `PACK-UNUSED-INPUT` and are not written; with two raw maps of one role the first by path is used. [M2, M13]
- Specular is copied unchanged into `_rmaos`/`_rfaos` A. [M3]

### Bake and RNM

- The roughness member decodes its own `_n` and bakes its variance (clamp t = 0.25); footprint lengths are a box pyramid; a pair whose sizes do not line up (not powers of two of one aspect) bakes from the `_n` fitted to the member's size (Note HD2), so no size pair is refused. [E, R4, R5, HD2]

- sRGB roughness raises `TAG-CONTENT-MISMATCH` and does not bake. [R10]
- The baked `_n` is recorded in the manifest sources with its decode settings, so `if-changed` sees it. [R12]

- **FM29 Automatic power of two; `resize` is Half, Quarter or Eighth with a size floor (plan task 18, 2026-11-03).**

The shorter side S is scaled by the same factor first, Ss = S·L'/L (L' the rounded longer side), then rounds up to its next power of two when Ss ≥ 0.85 of it, else down; Ss < 1 gives 1. Examples (test `resize::pot_rule_examples`): 1000² → 1024², 1024×768 → 1024×512, 1000×600 → 1024×512, 48×40 → 32×16, 3×5 → 2×4 (then `DIM-SMALL`), 900×1 → 512×1. - **HG2 A colourless set the user explicitly made Advanced skin is shared (agent ruling).** On `cs`, a set whose explicit shader (`set_shaders` or `set:x.shader=`) is Advanced Skin and whose members are all `_n` or `_sk` has `TextureSet.shared_skin`, set by `group::mark_shared_skin` before the `_wet` and `_detail_n` joins: other skin sets use its maps. `pack::plan::set_is_advanced_skin` is true for it, so its members type `pbr_normal`, `skin_sk`, `skin_wet`, `skin_detail`; it has no diffuse and builds no `_rfaos`, and `SHADER-MISSING-MAP` and `SHADER-EXTRA-MAP` are not raised for it. Narrower than the retired shared-skin plan: there is no same-name rule, and a lone `_sk` or `_n` with no explicit shader stays as before (`normal`, `backlight_tint`, the `skin` pick). A set edit that gives a shared set a colour map or any other kind of member, or empties it, unmarks it (`group::unmark_shared_after_edits`, using `member_split` because a joined `x_wet` has no suffix of its own); a set emptied by a hand move keeps its joined `_wet`. A shader change is part of the request signature, so the fast re-plan answers GLOBAL_CHANGE and plans in full; the flag comparison in `skeleton.rs`'s `same` is a defensive check only, which no user path reaches. Off `cs` nothing is shared.
- **HG3 The `_wet` and `_detail_n` joins see the explicit shader (agent ruling; supersedes the limit in DV7).** `prepare` computes `explicit_shaders` before `join_members`, so an `x_wet` or `x_detail_n` joins a set that is Advanced skin only by its chosen shader, as it joins one with an `_rfaos`. An explicit shader other than Advanced Skin now decides the `_wet` and `_detail_n` join alone: the set's maps are not consulted, so a set with a real `_rfaos` and an explicit Skin shader no longer joins its `_wet`, and those maps stay in their own sets. DV7's other half (step 6's packing prediction adds `rmaos`) is unchanged.
- **HG4 `shared` is derived in the GUI; a shared set shows only its maps (agent ruling).** `SetView.shared` is set by `finish_view` (`sets::is_shared`): the pick is Advanced Skin, the set has members, and every filled slot and every member is Normal, `_sk`, `_wet` or `_detail_n` (a member in no slot, such as a kept DDS with no job, is judged by its name through the engine's `member_split`). That follows the engine's member rule (`group::unmark_shared_after_edits`); the plan's narrower test (no Diffuse, no Rmaos) called a set shared after a hand-added `_p` that the engine had already unmarked, and hid that map's row. The statics choice ("PGPatcher entry for statics") on a shared set is disabled with the reason on hover and as a line, and its status line is not drawn: a shared set has no diffuse, so it writes no PGPatcher entry; the rest of its CS PBR records section and the Advanced tab stay. `TextureSet.shared_skin` is not carried over `SetResolved`, which is a serialised report. A lone `_rfaos` is not shared and keeps its missing-diffuse row. A shared set's card pill reads "shared" (hover "shared skin maps (no JSON)"); `shared_cells` keeps only Normal, `_sk`, `_wet` and `_detail_n` cards in the set editor, the set card and the card height. It writes no `.csskin.json` and raises no skin skip row (`cs_skin_json::build_plan`), takes a `_wet` or `_detail_n` drop (`choice_allowed`), and the name-tail readers (`member_tail`, `renamed_output`, the Rename dialog) read `_wet` and `_detail_n` as tails for it as for a skin set. `input_name.rs` reads a set's diffuse first, so a shared set never reaches it; it takes the same argument for consistency.
- **HG5 A mapped set writes to its texture set record's paths (owner for R1, the stored block and the key; agent ruling for the rest).** `[sets.txst]` holds `plugin`, `formid`, `edid` and `slotN` strings (the record's 1-based lighting slots, as `Subtype::txst_slot` gives; `TxstMap` in `sets_doc.rs`), with `no_fill = ["slotN"]` beside it; both are reserved keys, so they never reach the PGPatcher JSON. (a) **R1, owner:** a file in a slot the record names writes to that path; the `.csskin.json` follows its diffuse because it is built from the diffuse's output. (b) **The key is plugin + formid (owner, 2026-11-06: "edid within a plugin itself is not a forced unique"); `edid` is a label.** (c) **Path rule:** `txst_map::record_rel` works from `item.key` and the root's `textures` component, mirroring `discover::game_path`: `record` lower-cased, `textures/...dds`, no `..`; a `textures` folder in the key gives the components before it plus `record`, else the root's last `textures` folder must prefix `record`, else the rel is `record`. A record that fails it is never written (agent ruling). (d) **R5, agent ruling:** a file with no record slot (`_wet`, `_detail_n`, a slot the record leaves empty) keeps its path, with no warning. (e) **R10, agent ruling:** record path, then `output_name`, then the default; input names are untouched. `engine_inputs` extends the record paths after `named` off `cs` and, on `cs`, inserts them last under the same `mirrored` and `seen` checks. (f) **R11, owner:** two sets on one record path give the existing duplicate row (`path_collisions` reads the record paths too). (g) A PBR set on `cs` ignores its mapping (agent ruling; its prefix names its outputs). Skin behaviour stays `cs`-only. No `encode_version` arm changes.
- **HG6 Record paths win per output key and collide on every target (agent rulings; overrides the brief's insertion order, from the Task 4 review).** (a) `engine_inputs` applies precedence per key first: a key with a record path drops its `output_name` and prefix paths, and only then do the `mirrored` and `seen` duplicate checks run, on final paths. The brief inserted the record last, so a name it had replaced still reserved its path and blocked another set's record there. A record path that loses the check leaves its file on its default path (its `output_name` too). (b) Record paths take those checks on every target, so a second set on one record path keeps its default path and its job and planning is stable; `path_collisions` reports record collisions on every target (off `cs` only record rows) and `export_blocks` stops the export. Off `cs` with no mapping nothing changes. (c) An `output_name` takes its folder and suffix from the file's default output as it is now (`sets::default_output_key`): its key, its `[inputs]` alias and the suffix aliases through the engine's `apply_read_as` and `canonicalise_outputs`, and for a packed output `pack::plan::virtual_input` on its first source. It never reads `job_key`, which a record mapping moves, so no mapping can reach it: removing or undoing a mapping restores `textures/a/steel.dds` and `textures/a/steel_rfaos.dds`, and an input renamed into another folder takes its name there. (d) `record_rel` normalises the record's spelling: lower-case, `/`, empty and `.` components dropped, `..` refused, and the final relative path is checked; `TxstMap.slots` keeps the text as stored. (e) Containment is by path components only; a junction the user made inside the export folder is followed, as for every other output (`shortcut:` in `record_rel`; upgrade when the engine's write boundary resolves real paths).
